# 训练环境准备

工作台控制端与 GPU 计算环境分开。软件提供连接、数据传输、任务管理和校验；用户自行准备硬件、驱动、依赖、权重与账号。

| 使用方式 | 用户准备 |
| --- | --- |
| 本机 GPU | Windows NVIDIA 驱动、WSL2 Linux x86_64、可访问的本机 root SSH/SFTP 服务 |
| 云端或远程 GPU | Linux x86_64 NVIDIA GPU 主机、网络和 root SSH/SFTP 账号 |

当前执行器使用 GPU 0。Windows 原生 Python 不是训练入口。首次本机登记选择“首次登记本机 WSL（SSH）”，填写自己准备的回环连接；远程选择 SSH，填写主机、端口与账号信息。

## Python 和运行库

使用独立 Python 3.10–3.12 环境，当前校验支持：

| CUDA 构建 | PyTorch | Torchvision |
| --- | --- | --- |
| cu121 | 2.3.0+cu121 | 0.18.0+cu121 |
| cu128 | 2.7.1+cu128 | 0.22.1+cu128 |

Ultralytics 固定 8.4.203，NumPy 1.26.4、opencv-python 4.11.0.86、dill 0.3.8。其他基础依赖由上述包及连接报告列出。RTX 50 系列采用支持该设备的驱动和 cu128 组合，不能仅凭“CUDA 12”判断可用。

示例：在自己创建的 Linux 虚拟环境中手动安装 cu128 组合：

```bash
python -m pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128
python -m pip install ultralytics==8.4.203 numpy==1.26.4 opencv-python==4.11.0.86 dill==0.3.8
```

版本来源见 [PyTorch 官方历史版本](https://pytorch.org/get-started/previous-versions/)。WSL 使用 Windows 提供的 GPU 驱动，准备方式见 [NVIDIA WSL 指南](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)。管理员需确保环境在非交互 SSH 命令下可用。

## 工作目录与权重

支持的计算工作目录为 `/root/.vision-workbench` 或 `/root/autodl-tmp/vision-workbench`，选择目录需可写、有足够磁盘空间，Python 使用绝对路径。

在工作目录的 `weights` 子目录自行准备可信预训练权重：

| 文件 | 用途 |
| --- | --- |
| yolo26n.pt | 基础检测，启用设备必需 |
| yolo26n-seg.pt | 基础实例分割 |
| yolo26m.pt | 高精度检测模式 |
| yolo26m-seg.pt | 高精度实例分割模式 |

缺少可选权重时仅相应模式不可用。软件按固定 SHA-256 核对，具体文件来源和缺失项在连接报告中展示。软件不自动下载权重或安装训练库。

## 连接与校验

打开“训练与结果 → 训练设备与连接 → 连接设置”，选择连接方式、核对服务器主机公钥、输入凭据及 Python/工作目录。

先检查依赖和 SFTP，再点击“校验训练能力”。校验运行 GPU 身份检查、CUDA 运算、NMS、已有模型加载与小尺寸前向，不执行训练。缺失项包含处理操作；通过后点击“启用此训练目标”。GPU 正被工作台任务使用时，待任务结束再校验。

TensorRT 推理还需用户准备独立加速环境，产线包在目标设备中构建引擎。CUDA11/TensorRT8.6 与 CUDA12/TensorRT10.9+ 配置按目标环境选择，RTX50 需要适配其架构的 CUDA12.8+ 运行库和驱动；最终以目标端检查结果为准。
